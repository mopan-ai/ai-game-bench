# Public submissions

Real, task-scoped contributor evidence lives in `<submission-id>/rNNN/`.
Each revision has a `manifest.json`, creation/evaluation records and an explicit
file allowlist. Revisions may add cost or scoring evidence to the **same attempt**;
they are not automatically new generations.

The [results index](../reports/README.md#accepted-evidence) links submitted
packages to their task versions, maintainer decisions and reports. It is the
entry point for current acceptance status; old packages retain their original
submission-time statements.

## Read or contribute a package

- [Submit a result](../docs/submissions.md) explains what to record and how to upload.
- [Examples](../examples/README.md) demonstrate the format with invented data.
- [Review a submission](../docs/reviewing-submissions.md) defines the maintainer checks.
- [Reviews](../reviews/README.md) holds additional reviewer evidence when collected.

Structure checks do not authenticate a trajectory or independently grade a game.
Accepted evidence retains its limitations. Keep existing revision bytes unchanged;
submit corrections as a new revision. Read the [public-data terms](../docs/public-data.md)
before uploading; raw jobs, credentials and browser profiles stay local.
